# @metaworkflow/client-ui-mw-projects

[English](README.md) | 中文

## 概述

MetaWorkFlow profile 打开的是项目首页而非会话。首页列出 Host 已注册的项目——每个独立工作流一行，带有目录、实时状态、会话数与定义版本——并通过 `projects` Remote 命名空间新建、打开、重命名与删除。打开项目后切到它的工作台：把保存的定义画成流程图、运行控制与运行历史、带工具开关与执行记录的节点详情、项目统筹仍欠着的决策，以及就地渲染为共享 Conversation 的统筹会话。本包同时发布启动策略，让首屏停留在该首页。

## 使用本包

`mwf metaworkflow` 打开首页。页面标明这是该 profile 的主页，说明一个项目承载一条独立工作流，并展示加载骨架、加载失败、空状态或项目列表。

### 加载、空状态与失败

首屏在三行骨架中等待 Host 应答，骨架带有本地化的加载标签与 `aria-busy`。没有任何已注册项目时，首页给出 **新建项目**。列表调用失败时，面板显示该失败码对应的本地化原因、下方附 Host 自身的诊断信息，并提供重新发起调用的 **重试** 按钮。

### 新建项目

**新建项目** 注册一个标题为本地化「未命名项目」的项目，目录由 Host 决定，位于 Harness home 之下。Host 回执到达后行即出现，随后可用 **重命名** 给它一个真正的名字。

**使用小说模板** 注册一个标题为「小说创作」的项目，通过 `projects.importDefinition` 把内置的小说工作流写成它的第一版定义，然后打开它。模板是 `src/client/templates/` 下的一份 JSON 文档：`prepare`(Python) → `draft`(Agent) → 并行的 `review-style` 与 `review-consistency`(Agent) → `gate`(Python，等待两份审核) → `publish`(Python)，任一审核不通过时 `gate` 回边到 `draft`，最多三轮。两个审核节点使用不同的工具选择——文风审核用 `read`，连贯性审核用 `read` 与 `grep`，起草节点用 `read` 与 `write`——因此模板演示了重开项目后仍然保留的逐节点工具列表。Host 在写入版本前校验这份文档，所以校验不过的模板会被拒绝而不是写入；`tests/novel-template.host.spec.ts` 对随包发布的文件运行同一个校验器。

**导入 Mermaid** 打开一个对话框，包含项目名与流程图源码。提交时调用 `projects.importMermaid`：Host 注册项目、解析流程图、翻译成定义，并把它作为项目的第一个版本写入——被拒绝的流程图不会注册任何东西。成功后对话框自行隐藏、列表重新加载，组合随后打开新项目的工作台。拒绝是结构化的而不是一句话：对话框给出解析器指出的行号、拒绝码、翻译成功但无法运行时的校验消息，以及重新提交同一份草稿的 **重试**，因此一个笔误不会连累文本与项目名。

### 项目行

每行显示标题、项目绝对目录、目录实时状态（`目录就绪` 或 `目录缺失`），以及一行会话数与定义版本。

- **打开** 调用 `projects.open`：当目录存在但还没有数据库时，Host 会物化该项目数据库。Host 应答后，组合把主列切到该项目的工作台；该行保留 `aria-current` 标记，首页上也会点名已打开的项目，因此从工作台返回时能看出当前是哪一个。
- **重命名** 把标题换成行内编辑器。按 Enter 或 **保存** 提交去掉首尾空白的标题，按 Escape 或 **取消** 放弃，空草稿无法保存。
- **删除** 先就地确认：确认按钮点名该项目，并重申只移除注册。项目目录与其中所有会话都保留在磁盘上；列表下方的提示会再说明一次。

有变更在途时，行内控件与新建操作都会被禁用。变更失败时列表保持不变，并在其上方显示本地化原因与 Host 诊断信息。

窄屏下每张卡片改为纵向排列——先 Host 事实，再单独一行的操作——因此不需要横向滚动。

### 项目工作台

打开项目即选中它的工作台面板。头部有 **返回项目管理**、项目标题与目录，以及 **切换项目**：它列出每个已注册项目并标出当前项目，选中另一个会调用 `projects.open` 并留在工作台。切换失败时当前项目仍留在屏幕上，原因就地显示。

工作台的三块区域都读该项目最新保存的定义（`projects.definition`）：

- **工作流画布** — 把保存的定义画成 Mermaid 流程图：每个定义节点一个节点、每条边一支箭头，带条件的箭头显示条件文字。点击节点（或用 Enter、空格按下它）即为详情选中它；选中节点用更粗的品牌色描边，每个节点按它最新一次激活的状态着色（`succeeded`、`running`、`failed`、`waiting`、`pending`）。Mermaid 懒加载，从不打开项目的首页不会为它付出成本；渲染在 `securityLevel: 'strict'` 且关闭 HTML label 下进行。**放大**、**缩小**、**还原** 在自己的滚动区域内缩放这张图。Mermaid 拒绝渲染时，原因与本次交给它的原文会留在屏幕上并附带 **重试**，因为那份原文是区分「定义不支持」与「Mermaid 出错」的唯一依据。**运行** 从最新版本开始一次运行（Host 校验保存的定义、建运行并推进一次），**暂停** 停止继续派发，**继续** 重开已暂停的运行。没有可执行定义时三个按钮全部禁用，下方的说明给出原因；保存的定义不再通过校验时，这里列出校验问题而不是流程图。
- **运行历史** — 项目记录过的每次运行，最新的在前，带状态、它执行的版本、开始时间、结束时间，以及调度器记录的原因。列表经 `projects.runs` 读取，并与运行本身使用同一个定时器重读，因此在面板打开期间结束的运行无需刷新就会出现。
- **节点详情** — 画布中选中节点的详情，分三个 tab。**配置** 显示可写的标题，以及只读的类型、Python 源码或 Agent 指令、记忆策略、输出结构与汇合方式。**工具开关** 为 Host 注册的每个工具各列一个开关，节点仍声明的名字也保留，但只有已注册的工具可写：部署没有注册的名字会带着原因列出且无法切换，因此详情永远不会写出这个组合跑不起来的定义。**输入输出记录** 显示节点的输入绑定、输出结构，以及最新一次运行的每次尝试和它记录的失败。Python 节点没有工具开关，它的空状态也照实说明。
- **项目统筹** — 项目正在等待的决策：提问的节点、问题本身、它给出的候选项，以及经 `projects.answerDecision` 答复的快捷输入框；**刷新** 重新读取。决策下方直接渲染统筹会话本身——即共享的对话内容：面板保留该会话的引用，经渲染器的 `SessionProvider` 绑定作用域，并以聊天视图渲染 `conversation.content` 工厂。旁边仍保留 **在新标签打开统筹会话**，用于回到完整会话视图。

宽屏下画布与详情在中列、统筹在右侧；窄屏收起为单列，并显示 **画布** / **详情** / **对话** 的分段切换，因此三栏不会互相挤压。

### 启动策略

本插件发布 `sessionRestorePolicy`，值为 `restoreLastSession: false`。该可选策略的契约由 [ui-workspace](../ui-workspace/README.zh.md) 定义：策略缺省时，启动会重新打开上一次选中的会话；策略为 `false` 时，启动会把首屏让给组合所选的首页。首页在每次激活时只选中自己的 main 面板一次，因此该 profile 落在项目首页而不是某个会话上。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现内部细节——点击展开</summary>

本包从同一个 `ctx.slots.inject` 生成器注册两个 keyed `main` 面板——`projects` 与 `project`——因此两者随同一份声明出现与消失；另有一个使用 `projects` id 的 `sidebar.panellist` 入口，使侧栏在打开会话后仍能回到首页。生成器在两个面板之间共享同一个打开回调：只有首页行与工作台切换器会调用它，而工作台在 Host 确认打开之后才被选中。贡献已收拢后才落定的调用会被丢弃，而不是去选中一个已不存在的面板。

`ProjectsController` 是 `ctx.remote.projects` 之上不依赖 React 的对象层。它持有唯一一份 `ProjectsSnapshot`——列表状态（`loading`、`ready`，或带失败信息的 `error`）、项目行、选中项目、最近一次变更失败与变更在途标志——并把它发布为裸 observable。每次变更都用 Host 的回执更新快照，而不是乐观的本地草稿；被拒绝的调用会被折算进同一套失败码，而不会逃逸成未处理的 rejection。`open()` 还会报告 Host 是否真的打开了该项目，组合据此只在成功时导航。插件随组合一起发起首次加载，并通过 inject 的 `hooks` 舱把该 observable 交给两个面板，因此每个组件读取 `useProjects`、调用自己那份注入的回调。

`WorkbenchController` 是第二个 React-free 对象层，面向同一个命名空间。它拥有一个 `WorkbenchSnapshot`——统筹会话标识、定义与其校验问题、选中节点、该节点的工具开关、等待中的决策、最新运行及其激活和该运行的尝试——并把它作为裸 observable 发布。`open()` 整体替换快照并并行读取四个动词，代数计数器会丢弃更早的慢读，因此切换项目不会把旧节点发布到当前项目上。每次编辑与每个运行控制都走 `mutate()`：它先发布在途标记，把失败折进快照，然后重新读取定义与它保持选中的节点。

组件只持有本地状态：首页上是正在重命名或正在确认删除的行，工作台里是窄屏分区、节点 tab、标题草稿、决策答复草稿与项目菜单。文案位于以 `client-locale` 注册的 `mw.projects` 词典中，中文为基准侧；失败码到文案的映射表由两个面板共用，位于 `failures.ts`。`locale/` 下的语言文件只承载插件的展示元数据。

</details>

<a id="model-experience"></a>
## 模型体验

### 项目首页面板

#### 模型看到什么

没有模型可见输入。本包只在 `projects` main 面板中渲染浏览器侧项目状态，不贡献提示词文本、工具 schema 或请求上下文。

#### Token 影响

对模型请求没有直接影响；只有挂载本包并改变 agent 可见内容的组合才会产生影响。

#### KV 缓存影响

无影响：本包从不新增、替换或重排模型上下文。

### 项目工作台面板

#### 模型看到什么

没有模型可见输入。`project` main 面板把所选项目保存的定义渲染成流程图，并渲染它的工具开关、决策、运行状态与运行历史，还内嵌统筹会话的对话内容——后者只通过该会话自己的轮次影响模型，与共享会话视图完全一致。这个面板自身不向请求添加任何东西。

#### Token 影响

对模型请求没有直接影响。

#### KV 缓存影响

无影响：不新增、替换或重排提示词文本、工具 schema 或请求上下文。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **没有列表实时流** — 首页在激活时加载，并用变更回执修补行；另一个窗口的注册要等重新加载后才出现。
- **Mermaid 随包打进来而非共享** — 流程图渲染器是本包的私有异步 chunk（过线约 1 MB），第二个要画定义的界面会各自带一份。共享渲染器应当落在 `ui-primitives` 旁边的静态库里。它被压成一个 chunk 而不是 Mermaid 自己的分包：Client 模块加载器只会物化工厂请求的那一个 chunk，Mermaid 跨 chunk 的同步 require 在模块表里没有条目。
- **每次定义改版都会重画** — 改一次标题就会重新渲染整张图并让 Mermaid 重新布局。后续是比对源码差异或缓存布局。
- **图不是运行的实时视图** — 节点颜色来自工作台轮询到的最近一次运行，运行中的激活要等下一个四秒读取才会上色。
- **启动运行要等第一次 tick** — `projects.startRun` 在调度器停止派发时才返回，长跑的 Agent 节点会让请求一直挂着，而不是流式回报进度。后续是运行状态订阅。
- **决策靠轮询而非推送** — 工作台按四秒定时器、每次操作后以及点击 **刷新** 时重新读取 `projects.pendingDecisions`，没有订阅 `workflow/decision-requested` 与 `workflow/decision-answered`；因此决策最多会晚一个轮询周期出现。
- **只有标题与工具列表可写** — 指令、源码、schema、输入与边在详情里保持只读，那些修改归统筹会话。
- **工作台不保留按项目区分的视图状态** — 切换项目会沿用当前分区与节点 tab，刷新后不保留。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者工作上下文——点击展开</summary>

本包靠六处机制互相支撑，改动其中一处就要复查其余。数据归 Remote：项目行、变更回执与失败都经 `ctx.remote.projects` 到达，Host 应答慢时保留本地草稿从来不是解法。`ProjectsController` 是快照的唯一写入方——`load()` 把 `loading` 一次性推进到 `ready` 或 `error`，每次变更只在该列表状态之上叠加 `busy` 与 `mutationError`，而 `busy` 统计在途调用数，因此重叠的变更会一直禁用控件，直到最后一次落定。就绪闸门在 `view.status !== 'ready'` 时让新建与行内变更保持禁用，因为加载失败的列表没有可修补的行。两种失败形态折叠成同一个 `ProjectFailure`，两个面板共用的失败码到文案的表必须覆盖该命名空间可能抛出的每个码。文案位于 `mw.projects` 词典，中文为基准侧；`locale/*.json` 只承载展示元数据。

工作台面板是同一份快照的消费方，而不是第二个控制器：它从 `openedProjectId` 推导当前项目，该 id 消失时渲染项目列表的空状态——删除操作留下的正是这种状态。它的窄屏布局是作用在面板自身宽度上的 CSS 容器查询加上一份本地分区值，因此宽度判断不依赖窗口，侧栏的有无也不会把三栏挤压到一起；CSS 的单列过滤以 `data-active` 标记为键。统筹区域是静态文案而不是复用 `conversation.content`：那个座位渲染的是绑定会话的对话，而统筹自己的会话随它的里程碑落地。待定问题：用注册表变更流替代激活时重新加载，取决于 Host 命名空间是否先提供该流。

</details>
